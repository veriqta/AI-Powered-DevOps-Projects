# Support

## Where to begin

Read the selected project's prerequisites, getting-started guide, and troubleshooting section before opening an issue.

## Use GitHub Issues for

- Reproducible documentation errors
- Commands that fail in a supported environment
- Broken tests or fixtures
- Incorrect expected results
- Accessibility problems
- Missing or unsafe cleanup steps

Include the project number, operating system, tool versions, command used, sanitized error output, expected result, and troubleshooting already attempted.

## Do not use public issues for

- Vulnerability disclosure
- Credentials or private logs
- Production incidents requiring immediate response
- Personal account or billing information
- Requests to complete assessments or portfolio submissions on someone's behalf

Security concerns must follow [SECURITY.md](SECURITY.md).
